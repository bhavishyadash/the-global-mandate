# Foundation acceptance record

This distinguishes the implemented M1 technical baseline from full foundation signoff. Evidence is current through session 65. No percentages imply completeness or a release date.

| Criterion | Evidence | Remaining qualification |
|---|---|---|
| Headless simulation and clock | Five bounded Godot suites run in CI; date, pause, speeds, decisions and calendar are tested. | One active simulated country; not a coupled world. |
| Scenario data and IDs | Two fictional v2 scenario files validate country, political, service, institution and diplomacy state; v1 defaults remain supported. | Three groups/parties, fixed services and partner IDs; laws and behavior are still code. |
| Decisions and events | Validated command IDs return explicit results; bounded categorized dated records support filtering. | Public dictionaries and direct methods remain mutable; events lack structured actors/causal payloads. |
| Persistence and reproducibility | Save v16 validates candidate state before rotation; older saves migrate; seeded state, replay and ten-year save/reload stress tests pass. Session 65 tested preserved interrupted artifacts and an actual blocked backup rename; [recovery instructions](SAVE_RECOVERY.md) explain manual recovery. | Other filesystem failures, power-loss durability and stochastic gameplay are unverified. |
| Build and test automation | GitHub Actions runs Python and Godot suites and tests both scenarios in an exported resource pack. Session 56 built a Windows executable and PCK, checked headless and graphical startup, and advanced a day. Session 57 verified a new build starts maximized and can be restored on the current machine. | Installation, upgrades and operation on target hardware are unverified; CI does not export the standalone binary. The restored window appeared small. |
| Initial performance | Session 65 measures 365 days for 2, 50 and 200 synchronized fictional countries; p95 tick times on the current Windows machine were 0.050, 1.221 and 4.700 ms. | Single synthetic run; workload lacks trade, geography, AI and realistic diversity. No target-laptop, frame-rate or memory measurement exists. |
| Visual smoke | In Godot 4.7.2, advanced a day, issued an executive directive and inspected its history. In the standalone build, saved and restored a date/cash state, switched scenarios and restored the original saved scenario. Session 65 inspected the Overview and Laws screens. | Tests were on the current machine. The restored window is very small; 720p, accessibility, target laptop and director playtesting remain open. A prototype test save slot was created in session 61. |

The provisional minimum is a Windows laptop with four CPU cores, 8 GB RAM, integrated graphics and a 720p display. Initial design goals are a usable 720p interface and at least 30 frames per second during ordinary interaction, with graphics options available as visual features grow. Simulation speed targets need a representative coupled-world workload before they can be defined responsibly. The director chose to leave target-hardware validation open for later. These are goals, not measured results or a guarantee that the current prototype meets them.

M1's core technical baseline is implemented and tested, with the target-hardware and broader quality checks explicitly deferred rather than treated as passed. The headless multi-country registry is not integrated with the playable screen or the older diplomacy model. M2/M3 and the economy, institutions and diplomacy milestones contain prototypes, not their full acceptance scope; no claim of a complete or release-ready game follows from completing the core baseline.
